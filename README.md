## Төслийн бүтэц

- `src/main/java/mn/edu/must/sqat/GradeCalculator.java` — тестлэгдэх класс (`letterGrade`, `totalScore`)
- `src/test/java/mn/edu/must/sqat/GradeCalculatorTest.java` — нэгжийн тестүүд
- `results/mvn-test.txt` — бүх тест ногоон (PASS) гаралт
- `results/mvn-test-mutant.txt` — санаатай мутаци (`>= 90` → `> 90`) оруулсны дараах гаралт

## Тестийн тоо

`GradeCalculatorTest` класс дотор нийт **14 ширхэг `@Test`** метод (ердийн утга, хязгаарын утга, буруу оролт) болон **2 ширхэг `@ParameterizedTest`** (нэг нь `letterGrade`-д 9 мөр, нөгөө нь `totalScore`-д 3 мөр `@CsvSource`-той) бичигдсэн. Surefire `@CsvSource`-ийн мөр бүрийг тусдаа тест гэж тоолдог тул нийт ажиллах тестийн тоо:

> **14 (ердийн @Test) + 9 (letterGrade параметр) + 3 (totalScore параметр) = 26**

Энэ тоо `results/mvn-test.txt` файлын сүүлийн мөртэй яг таарч байсан:
```
Tests run: 26, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

## Мутацийн тест

`GradeCalculator.letterGrade`-ийн доторх нөхцөлийг:

```java
if (score >= 90) return "A";
```
гэснийг санаатайгаар
```java
if (score > 90) return "A";
```
болгож, дахин `mvn test` ажиллуулсан. Үр дүн `results/mvn-test-mutant.txt`-д хадгалагдсан:

```
Tests run: 26, Failures: 2, Errors: 0, Skipped: 0
BUILD FAILURE
```

Доорх **2 тест** энэ мутацийг илрүүлж, унасан:

| Унасан тест | Шалтгаан |
|---|---|
| `ninetyIsExactlyA` | `letterGrade(90.0)` нь `"A"` байх ёстой байсан мөртлөө `"B"` буцсан |
| `letterGradeBoundaries[2]` (parameterized, `"90,A"` мөр) | мөн адил `expected: <A> but was: <B>` |

Үлдсэн 24 тест (ердийн утга, бусад хязгаар, буруу оролт) бүгд ПАСС хэвээр байсан — учир нь энэ мутаци зөвхөн яг 90.0 утгад л нөлөөлдөг. Мутацийг илрүүлсний дараа кодоо `>= 90` болгон буцааж засаад, `mvn test`-ийг дахин ажиллуулж, `results/mvn-test.txt` файлыг дахин ногоон гаралттайгаар хадгалсан.

## Дүгнэлт

Энэ лабораторид хамгийн хэцүү байсан хэсэг нь JUnit 5-ыг зөв ажиллуулахад шаардлагатай pom.xml-ийн тохиргоо байлаа — ялангуяа surefire plugin-ий хувилбар болон maven.compiler.release-ийн асуудал, мөн тестийн файл санамсаргүйгээр `src/main/java`-д биш `src/test/java`-д байх ёстойг анзаарахгүй байх эрсдэлтэй байв. Эдгээр нь кодын логикийн алдаа биш, харин төслийн бүтцийн алдаа байсан тул олж засахад илүү их цаг зарцуулагдсан. Хязгаарын утгуудыг (90, 89.99, 60, 59.99, 0, 100) тусад нь шалгасан нь маш ач холбогдолтой болохыг мутацийн тест тодорхой харуулсан — хэрэв зөвхөн 95, 85, 30 гэх мэт "аюулгүй" утгуудаар тестэлсэн бол `>= 90`-ийг `> 90` болгосон алдаа огт илрэхгүй өнгөрөх байсан. Мутацийн туршилт миний бичсэн availability сценариогийн (90.0 оноо яг A байх ёстой гэсэн) хэмжүүрийг шууд баталгаажуулсан — 2 тест яг таг уг алдааг зорьж илрүүлсэн нь тестийн чанарын шууд нотолгоо юм. Хэрэв нэг ч тест унаагүй бол энэ нь хязгаарыг огт шалгаагүй гэсэн үг байх байсан бөгөөд "pass болсон тест зөв тест гэсэн үг биш" гэдгийг энэ дадлага бодитоор харуулсан. Parameterized тест ашигласнаар ижил логиктой олон тохиолдлыг нэг товч метод дотор нягт байрлуулж болохыг мөн ойлгосон — гэхдээ Surefire мөр бүрийг тусдаа тест гэж тоолдог тул "8 метод" ба "Tests run" тоо хоорондоо ялгаатай болохыг анхаарах хэрэгтэйг энэ лабораторт тодорхой сурлаа.
